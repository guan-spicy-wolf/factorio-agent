# Factorio 蓝图生成：从坐标设计到生成器（第二版）

Oct 26, 2026 · @holo · 第一版（Oct 24）见 `design-v1-2026-10-24.md`

本版在第一版的基础上，按六轮验证实验（阶段 0–5a、6a、4a–4c，记录在 `docs/experiments/`、`docs/VERIFY.md`、`characterization/`）的结论修订。改动处用 **[修订]** 标出，第一版说对了的地方保留原文。

## 背景与动机

上一版卡住的根因是：设计 agent 工作在坐标层级，而蓝图只记录结果、不记录约束。本方案把 agent 的产出从"一张蓝图"改为"能生成一类蓝图的程序"。

上一版流程分四个阶段：选址、设计、仿真测试、部署。问题集中在第二阶段（逐格设计）和锚定建筑上：脚手架随约束种类线性增长、改进现有蓝图比从零设计更难、社区蓝图用不上、液体和固定建筑卡死。

**[修订] 验证结论。** 六轮下来，从矿到铁板、绿板、红瓶、绿瓶、塑料、硫酸的单元全部由生成器产出，零坐标手改，解析预测与 headless 实测偏差 ≤ 2%（绝大多数 0%）。方案的确定性底座成立。方案真正的押注"agent 不碰坐标后能否自行写出合格生成器"也测了两次（6a、4a）：在只给目标、约束、工具、不给排法的条件下，agent 分别改出了电杆零损失的采矿排法和一个从零编码的周期求解器，`validate` 失败 0 次。样本起初只有一个执行者（当前最强编码模型）；Oct 29 用 Sonnet、Haiku 各复现一次 6a（`docs/experiments/6a-replication.md`）：验收全过、`validate` 失败仍为 0，解的质量随模型变弱单调下降（钻机 375 / 355 / 346），差距在纸上分析而不在编码。

## 目标与非目标

**目标**（保留第一版，补一条）

- 给定产品和目标产率，自动产出达标的自由单元。
- 锚定单元在真实地图上由算法生成，其接口作为自由单元的硬约束。
- 上帝建造模式部署到真实地图，地形约束照常生效。
- **[修订]** 每个生成器家族有**解析预测模型**；特征化表只记录实测与预测的残差（见"特征化"）。
- agent 的输出是参数或生成器代码，不是坐标。

**非目标**（保留）：千瓶级、信标与 UPS 优化；让 agent 玩游戏；全局最优宏观排布；面积极致压缩。

**成功标准**（保留第一版五条，均已在仿真中达成；"端到端"目前到真实地图仿真，真实存档部署未做）。

## 核心方法

蓝图是 `generate(p)` 在某组参数下的一个输出，我们维护的是生成器本身；不变量由构造保证，`validate` 是最终裁判。

### 自由单元与锚定单元

保留第一版定义。**[修订]** 锚定单元的接口速率不是常数：采矿单元边缘钻机几秒采空、搜索区会混入邻矿。契约用 `rate_profile`（初始速率 + 采空时间下界）表达，生成器有"每钻最少矿量"与"不允许混矿"两个参数。地形以**快照**（可建格、资源格、水、已占格）作为地图与生成器之间的接口，生成器不直接依赖 RCON；真实地图流程固定为清障 → 快照 → 生成/路由 → 部署。

### 周期与生成器家族

单元结构仍是"头部 + 周期 × n + 尾部"。家族目前有三个：

1. 带供料的行（冶炼列）——经典排法参数化。
2. 配比周期的直插链（绿板、红瓶、绿瓶、塑料、硫酸）——周期由求解器得到。
3. 钻机铺矿（锚定）——沿带一维排布，电杆位置用动态规划。

**[修订] 配比不整齐**时的两种周期类型都已实现并由求解器自动选择：直插但让一侧过剩，或中间产物走输入带的一条道。按总机器数排序，平手取直插。

### 周期内求解与周期边界条件

**[修订] 这是第一版判断错得最多的一节。** 第一版担心"约束写起来比手写模板还难"，实验结论相反：

- **约束不难写**。约束几乎都是几何库的直接调用，第一版就对，求解器给出的周期从未被 `validate` 拒绝。手写模板只覆盖一种形状、换爪子就坏，而且要人先知道答案。
- **难的是搜索**。手写穷尽搜索 1300 行里大半是剪枝，绑定一种周期结构，换家族要重写；而且它的错是悄悄漏解，`validate` 抓不到。
- **搜索交给 CP-SAT**。同一问题 CP-SAT 版第一次就对，8 个变体与穷尽搜索结果一致；之后加红瓶约 80 行、绿瓶约 30 行声明式约束，配方专属代码 0 行；红瓶 1:3 的不可行穷尽版 300 秒证不出，CP-SAT 32 秒。默认后端 CP-SAT（OR-Tools 可选依赖，没装回退穷尽搜索），穷尽搜索只作无依赖回退与对拍基准。
- **加一类结构词汇的成本**：流体是第一类，不含测试约 750 行，求解器约束 186 行，其余一半落在求解器之外（几何库口位置随朝向、镜像、配方变；数据层；契约加温度与段长；三个新不变量；路由器段长检查；液体计量夹具）。
- **最优只在模型词汇内成立**，面积从来只是指标。证明过的 133 被加入长臂爪后的 108 打破，108 又被全调色板的 99 打破。所以求解默认为**随时可用**模式：宽松尺寸起步，首个可行解秒级（除绿瓶 53 秒外全部 ≤ 6.4 秒），时间盒内收紧并标注是否证明；证明最小只作离线或特征化作业。小时间盒内收紧收益很小，质量提升要靠分钟级后台时间。
- **组件以调色板给出**，求解器按成本选用子集，人不再预先挑等级。全调色板能找到人没想到的解（99），但 `compact` 预设平手时会挑最贵的等级，默认应以成本裁决（待做）。
- **求解器的盲区**需要专门的校验：小规模与无剪枝暴力对拍、保留已知可行周期作"必须能找到"的回归用例；CP-SAT 的错误形态是约束写过头，用不可满足核定位。

边界条件（保留并具体化）：周期为 W×H 矩形沿一轴平铺；足迹在矩形内；带行同向同级；物品不跨周期；用电体由本周期杆供电；杆连通且能连到下一周期的像。

### 接口契约

**[修订]** 契约已被连接算法消费过一轮并补全。现在包含：类型、物料、位置、朝向、带道、**端口下的实体**（带等级、杆种）、**按道速率**、`rate_profile`（固定 / 按需含上限、初始速率、采空下界）、**端口分组**（同一条带上的多个口，道要求挂在组上）、**端口空间要求**（进入方式与上游留空格数）、液体口的流量、温度与段长，以及结构化前置条件 `requires`（`LaneMaterial`、`MinRate`）。字符串 `assumptions` 只给人看，任何算法不得读取。路由器、放置、夹具只读契约，不回头查布局，并有测试证明。

尚缺：电接口功率；启动 / 缓冲填满时间；衰减曲线本身。**[阶段 7]** 红瓶站第一次被"缓冲填满时间"卡住：上游按产能跑、下游按需取，盈余灌满链路带要 1000–2000 s，没有它就定不出稳定段从哪开始；站点层用 `site_sweep.fill_time`（链路带 + 消费单元的带 ÷ 盈余）顶替，契约仍缺单元内部缓冲量这一项。电功率与衰减曲线没有卡住红瓶站（电源是夹具；窗口内矿区不枯竭由 `choose_mining` 保证）。

### 特征化

**[修订] 收窄。** 第一版设想"选参数靠查表"，实际上解析模型（`throughput.predict`）就是精确的，查表选参数是多余的，这条删去。仿真的真实价值是**发现缺失的不变量与假设**：电杆不自动连线、矿区采空与混矿、配方未解锁、段长上限、配方产能加成，全部来自实测与预测不一致的地方。所以：

- 特征化表只记录实测对预测的残差，并兼作回归测试；每条记录附带当时的运行时状态。
- 仿真只在两种情形触发：新实体类型或新结构词汇；轮末回归。日常循环是：可行解 → `validate` → 解析预测。
- 实测场景（上帝建造、全科技、无限供应）与真实存档不同，预测模型必须读运行时状态。

### 组件树与容器

第一版设想的容器（`Column(Row(...), Balancer, Row(...))`）**未实现**。实际走的是另一条路：单元放置 + 以契约驱动的路由（带、管、电，网格 A* 加地下段跳跃边，侧向汇入按道），在真实地形上把采矿单元接到冶炼列并达标。

**[修订，阶段 7 任务 A]** 多单元站点出现了（真实地图两矿 → 两冶炼列 → 红瓶直插链，`docs/experiments/7-red-science-site.md`），容器的问题有了答案：**不需要**。站点是"锚定单元 + 自由单元 + 链路"（`SitePlan`），自由单元按顺流顺序逐个放在"到已放邻居口的估算带长最便宜"的位置，路由器接通；每一级的规模由下一级的契约（`MinRate`）定。容器能提供的只有"组合内相对位置固定"，而规则逐个放一样能得到，且不需要人先设计组合；只有重复同一组合（n 条并列列 + 平衡器）时容器才省事，那是平衡器出现之后的事。放置里真正是**判断题**（交给 agent 而不是算法）的是：带长预算（下游离上游多远算合理）、占矿的代价、以及放置顺序的优先级；算法题是候选排序与碰撞。

## 系统分层与组件

**[修订]** 实际分层：

- **游戏数据导出**：`--dump-data`，按显式 mod 组合导出；种子文件由脚本从 dump 抽取，不手写（手写数据 24 处错）。
- **运行时状态**（新增一层）：科技加成、手持量、配方产能，从 force 读取，预测与特征化以它为键。
- **几何库**：占地、爪子取放、电杆覆盖与拉线、带道、液体口随朝向镜像配方的变换。
- **不变量**：`validate`，叠加契约一致性检查。
- **周期求解器**：周期模型 + CP-SAT 结构词汇 + 随时可用驱动；穷尽搜索回退。
- **生成器家族**：三个。
- **地形与站点**：地形快照、站点模型、放置规则、路由。
- **导出器 / 部署器**：蓝图字符串（写 `wires`）、蓝图导入复活 ghost、读回、清障。
- **仿真与实测**：headless 服务器、以微型单元表示的夹具、按 tick 计时的实测、`fgen verify` 假设测试。
- **假设测试**（新增一层）：VERIFY.md 的每条几何约定对应一个游戏内检查；版本或 mod 组合变更就是重跑一遍。2.0.76 → 2.1.23 迁移的四处 API 变动全靠它暴露。

## agent 的角色分工

原则不变：确定性计算和几何交给算法，判断和写代码交给 agent，家族划分和不变量交给人。**[修订]** 按实验更新：

| 工作 | 负责方 | 实验证据 |
| --- | --- | --- |
| 配比、机器数、杆间隔、周期内摆放 | 算法 | 全部由数据派生；周期由 CP-SAT 求解 |
| 锚定单元生成、单元间连接 | 算法 | 阶段 2、3a |
| ~~选家族与参数（查特征化表）~~ | — | 删去：解析模型直接算 |
| 读诊断、决定改什么 | agent | 6a：从 `pole_slot` 统计与渲染出发改排法 |
| 写 / 改生成器与求解器词汇 | agent | 6a、4a、4b、5a：只给目标与验收即可完成 |
| 定目标、验收口径、不变量与普通测试的边界 | 人 | 6a 里 `pole_slot` 口径被重定义；三个旧测试写死旧排法被改 |
| 组件等级选择 | 算法（调色板 + 成本） | 4c |

**[修订] agent 工作的固定循环**：分析（纸上先排除不可行的族）→ 小实验核对拿不准的游戏事实（几分钟，比推理便宜）→ 改生成器或词汇 → `validate` + 预测 → 必要时实测 → 记录迭代。记录是产物。两种模式的对比：有明确规格约 20 分钟，只有目标约 45 分钟，差距主要是前两步。

- **结构词汇的成本在求解器之外**：每类新结构约一半代码落在几何库、契约、不变量、夹具。这是人要持续投入的部分。
