# 阶段 3a 实施任务书：清障、夹具泛化与单元间连接

接续 `docs/plan-phase2.md`。目的不是把阶段 3 全部做完，而是用最便宜的方式检验**接口契约是否够用**：让一个确定性的连接算法只读契约，把两个单元用带子、管道、电杆接起来，在真实地形上仿真达标。资源按无限供应（夹具）给，不做选址 agent，不做真实存档部署。本文与 `design.md` 冲突时以本文为准。

## 1. 复盘结论对本阶段的影响

- 契约里的 `assumptions` 目前是字符串。本阶段把连接算法会用到的几条变成**可检查的结构化字段**（见 §3.1），字符串只留给人看。
- 锚定单元的速率随时间衰减。本阶段连接算法只用初始速率，但契约里要能放 `rate_profile`（初始速率、估计采空时间），由采矿生成器填。
- 仿真测试 ≠ 真实部署。本阶段全部是仿真：正常生成的地图 + 夹具 + 临时存档。

## 2. 技术约定

沿用阶段 0–2 全部约定。路由算法是纯函数，输入 `Terrain` 快照 + 已放置单元 + 连接请求，输出 `Layout`；单元测试用手写 `Terrain`，不起服务器。所有距离（地下带/地下管跨度、拉线距离、供电区）从种子取。

### 3.1 契约升级（`layout/model.py`）

`Interface` 增加：

- `rate_profile: RateProfile | None`：`initial`（= 现在的 `rate`）、`depletion_s_lower_bound`（锚定单元填，自由单元 None）。
- `requires: tuple[Predicate, ...]`：结构化前置条件，连接算法与夹具都要校验。先定义这几种：
  - `LaneMaterial(lane, material)`：该带道上只能是这种物料（冶炼列的"矿在左、煤在右"）。
  - `MinRate(value)`：输入至少这么多才达标（= 目标产率反推）。
  - `Compressed()`：假设输入满压缩（只记录，不校验）。
- `Interface.world(origin, transform)`：给出世界坐标与方向（放置后的接口）。

现有生成器（冶炼列、采矿）改为填这些字段；旧的 `assumptions` 字符串保留。

### 3.2 清障（`sim/clear.py`）

`clear_obstacles(rcon, area) -> dict`：销毁 `tree`、`simple-entity`（石头）、`item-entity`、`corpse` 类实体，返回各类计数；**不动**资源、悬崖、水、玩家建筑。`RconTerrain.snapshot` 之后再清障会让快照失真，所以流程固定为：清障 → 快照 → 生成/路由 → 部署。悬崖在快照里是不可建格，路由绕行。

### 3.3 夹具泛化（`sim/harness.py`）

- 源/汇/电源各表示为一个微型 `Unit`（`infinity-chest + loader` 的供料头、`loader + steel-chest` 的汇、`electric-energy-interface + 一根杆`），带自己的 `Interface`。这样连接算法对"夹具"和"单元"一视同仁：**夹具只是契约的另一端**。
- 分道供料：源头 Unit 的输出接口声明 `lane`，`LaneMaterial` 由路由用侧向汇入满足（§3.4）。
- 液体源/汇：`infinity-pipe`（设 `infinity_pipe_filter`，模式 `at-least` / `exactly`）；汇用 `infinity-pipe` 设为 0 或 `storage-tank` 读 `fluidbox`。先在实机确认 2.1 的字段名，记 VERIFY。

### 3.4 路由（`route/`）

通用：

- 网格 = 快照里可建、无水、未被任何单元或已路由实体占用的格；资源格可走但加代价；接口口正前方 k 格做保留带（防止别的路由把口堵住）。
- A*：4 邻接；代价 = 步数 + 转向惩罚；"跳跃边"表示地下段：从 `(t, d)` 跳到 `(t + n·d, d)`，`2 ≤ n ≤ max_distance + 1`，中间格不要求可走（可穿越水、悬崖、带子、管道），入口和出口格必须可走，代价 = 地下实体数 + 小惩罚。
- 输出 `Layout` 后对**整站**跑 `validate`，再按 `requires` 做契约校验。

**带子**（`route/belt.py`）：

- 直连：从生产者口沿其方向出发，到消费者口沿其方向进入（终点约束是"进入格 + 方向"）。两道物料不变。
- 侧向汇入（满足 `LaneMaterial`）：目标是消费者输入带上的某一格，从该带的左侧或右侧垂直汇入；汇入侧由要填的道决定（东向带填左道从北侧汇入，阶段 1 已实机核对）。多个生产者汇到同一条带时按道容量累计检查，超了报 `Infeasible`。
- 速率检查：`sum(initial rates) ≥ MinRate`，单道 ≤ 道容量，整带 ≤ 带容量；不满足给出建议（换带等级、分两条）。
- 带等级：取消费者接口所在带的等级，上游低等级时报警不报错。

**管道**（`route/pipe.py`）：

- 管 + 地下管，跨度 `max_underground_distance`。
- 邻接隔离：新管不能与任何非目标的液体连接点相对（复用 `fluid.unintended_adjacency`）；A* 把这类格标为不可走。
- 本阶段只测一条：`infinity-pipe` 源 → 隔着障碍 → `storage-tank` 汇，验证连通且 `fluidbox` 有量。

**电**（`route/power.py`）：

- 把所有单元的电接口（各自的第一根杆）和电源夹具并成一个网：按欧氏距离建 MST，每条边用一串杆铺路，杆间距 ≤ 两端中较小的 `maximum_wire_distance`，杆放在可走格上，放不下就沿边两侧找最近可走格；导出的蓝图写 `wires`（阶段 1 已有）。
- 验收：实机读 `electric_network_id` 全站唯一。

**冲突与顺序**（`route/connect.py`）：电杆占 1 格最灵活所以最后放；先带后管，或先管后带；任何一步失败就换顺序再试一次，仍失败抛 `Infeasible` 并指出是哪条链路、卡在哪一段。

### 3.5 最小放置规则（`site/place.py`）

不做选址 agent。给一个锚点和一个 Unit，在锚点附近螺旋扫描，找到第一个能放下 Unit 占地（加 1 格边距）的位置，可指定旋转/镜像候选。只服务本阶段测试。

### 3.6 整站仿真（`sim/site_measure.py`）

部署顺序：清障 → 快照 → 生成单元 → 放置 → 路由 → 部署全部 → 接夹具 → 跑 → 逐口实测。实测每个消费者输入口和最终输出口的速率，与契约（`MinRate`、`initial`）对比，写 `characterization/site.jsonl/.md`。

M1–M4 必须完成；M5 尽力；M6 必做。

## 5. 不要做的事

- 不做选址 agent、不做任何 LLM 调用。
- 不做真实玩家存档的部署与备份回滚。
- 不做平衡器、不做多带合流到一条带以外的流量重分配。
- 不改冶炼列和采矿的排法（电杆占位问题另开任务）。
- 不追求路径最优，可达且合法即可。
