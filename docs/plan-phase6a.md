# 阶段 6a 实验：agent 自行改进生成器

这不是实施任务书，是一次实验。方案（`docs/design.md`）唯一实质性的押注是"agent 的输出是参数或生成器代码，且能稳定通过不变量检查"。前三轮全部由人写详细排法、agent 照做，没有测过这一点。本轮反过来：**只给目标、约束、工具和验收，不给排法**。执行者（agent）自己设计布局、自己迭代，并记录过程。记录本身是实验结果，和代码同等重要。

## 实验规则

- 任务书不描述任何布局。执行者不得向人索要排法；拿不准就自己在仿真里试。
- 允许改生成器、几何库、不变量、路由器；不允许放宽现有不变量去凑结果，不允许在代码里写死数字或 if 实体名。
- 全程记录到 `docs/experiments/6a-<task>.md`：每次迭代的假设、改动、`validate` 结果、实测结果、为什么失败、下一步。失败也要记，记录比结果重要。
- 每个任务结束时统计：迭代次数、`validate` 失败次数（按违例类型）、实测不达标次数、总耗时。

## 任务 1：采矿单元的电杆占位损失

**现状**：`gen/mining_patch.py` 让电杆占用一个完整的 3 格钻位，小杆每两个钻位一根，杆那一侧丢掉约四分之一的钻机（`dropped_drills.pole_slot`，真实地图 10/42）。大钻配中杆因周期 11 > 拉线距离 9 基本不可用。

**目标**：在同一矿区、同一参数下，放下的钻机数显著增加，`pole_slot` 损失大幅下降；大钻配中杆变得可用。

**约束**：

- 阶段 2 的 7 个画矿用例与真实地图用例全部仍需通过 `validate`，每条带实测与契约偏差 ≤ 阶段 2 水平（0% 为基准，允许 ≤ 2%）。
- 电杆间距、供电覆盖仍由数据派生；换杆、换钻、换带只改参数。
- 接口契约的格式不变（输出口仍是每条带末端）。
- `characterization/mining_patch.{jsonl,md}` 用 `fgen sweep mining --measure --real-map` 重新生成，并在 `.md` 增加"改进前 vs 改进后"的钻机数与 `pole_slot` 对比。

**验收**：7 个用例 + 真实地图，`pole_slot` 总损失 ≤ 改进前的三分之一；钻机数不减少；实测全部达标；大钻 + 中杆在矩形矿区上能生成且通过 validate。

## 任务 2：契约补全与生成器、路由器的联动改造

**现状**：`docs/plan-phase3a.md` §6 列出契约缺的 8 项。本任务做其中可由生成器自己填、路由器实际会用的 5 项：

1. `entity`：端口下的实体名（带等级、杆种）。
2. 按道速率：`RateProfile` 按道给出，`both` 口两道各自的速率。
3. 按需供给：`RateProfile` 显式区分固定产率与按需（含上限），取消 `rate=None` 的语义重载。
4. 端口分组：同一条带上的多个口显式归入一个 `port_group`，道要求挂在组上。
5. 端口空间要求：`approach`（允许的进入方式：直连 / 侧向汇入 / 两者）与所需的上游空格数。

**约束**：

- 字段设计由执行者决定，但要写进 `docs/plan-phase3a.md` §6 对应条目后面的"已实现"说明。
- 两个生成器与所有夹具单元填全新字段；路由器与放置规则改为**只读契约**，删除所有"回头查布局"的旁路（现有的 `_belt_at`、按格归组、`PORT_CLEARANCE` 常量等）。
- 阶段 3a 的平地整站与真实地图整站实测结果不变。
- 旧的 `assumptions` 字符串可删可留，但不得再被任何算法读取。

**验收**：`grep` 不到路由器/放置/夹具从 `unit.layout` 反查端口实体的代码；261 个测试全绿且新增字段有测试；`fgen sweep site --measure --real-map` 结果达标。

## 顺序

先任务 1，后任务 2。任务 1 是实验主体；任务 2 是普通工程，用来对照"有明确规格"与"只有目标"两种模式下 agent 的表现差异，所以也要记录迭代。
