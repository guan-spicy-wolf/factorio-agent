### 0.1 绿瓶链契约（生成后核实）

（待 `generate` 返回后补：输入带数、各口的 `lane` / `MinRate`、尺寸。）

配方（种子数据）：绿瓶 = 1 爪子 + 1 传送带（6 s）；爪子 = 1 绿板 + 1 齿轮 + 1 铁板；传送带 ×2 = 1 铁板 + 1 齿轮；齿轮 = 2 铁板；绿板 = 1 铁板 + 3 铜线；铜线 ×2 = 1 铜板。所以每瓶：铁板 4.5（链内造齿轮、爪子、传送带）、绿板 1；每绿板：铁板 1、铜板 1.5。1 瓶/s 的站：铁板 **5.5/s**（绿瓶链 4.5 + 绿板链 1.0）、铜板 1.5/s；0.5 瓶/s 减半。铁板一条黄带（15/s）够，一条道（7.5/s）也够。

## 1. 纸上分析（规则 1）

### 1.1 "铁板去两处"的几族

| 族 | 做法 | 上限 / 代价 | 取舍 |
| --- | --- | --- | --- |
| A. 分离器单元 | 一个极小的生成单元：带 → splitter → 两条带；一个输入口（MinRate = 两边需求之和）、两个输出口（各自的计划份额）。路由器照常连；分配由背压决定（一边堵了全给另一边） | 上限一条带 15/s（够 5.5）；代价：生成器 ~100 行 + 站点流量预测要会算"多输出、按需分配"（现在 `flows` 假设每单元一个输出）+ 测试。n 个消费者用 n−1 个串联 | **选它**：唯一对"任何单元的任何输出分给多个消费者"都成立的做法，也是以后并列冶炼列 + 平衡器的词汇 |
| B. 双带采矿 → 两条冶炼列 | 一个矿区出两条带（`max_belts=2`），每条带供一条按各自消费者定规模的列，板不用分 | 零新实体；代价：`max_belt_rate` 要按带分别给（生成器改）、`choose_mining` 的四变体选择要变成多目标；只解决"在矿那一层分"，分不了链的输出（以后绿板给两处就不行）；多一条列 = 多一套煤夹具与路由 | 排除：不通用，且改的是已经稳定的采矿生成器 |
| C. 一个矿区切成两块、两个采矿单元 | 纯函数切 `Patch`，其余不变 | 两个单元的钻机搜索区（5×5）在切缝处重叠，`validate` 会报重叠；切法本身是又一个判断题 | 排除 |
| D. 四级直插链（绿板也在链里造） | 不用分流 | 4b 已算过：机器数翻倍（每瓶 1/12 爪子机 … 再挂铜线一级），9 台机器的周期证明要 31 分钟，16 台以上没跑过；而且铜板又要进链，输入带数变多 | 排除 |
| E. 冶炼列出两条带 | 冶炼列生成器加"两侧出料"或"出料带分两段" | 只对冶炼列成立；A 的特例且更贵 | 排除 |

A 的"判断题"：分离器放哪（放置规则给——它有一个上游、两个下游，顺流顺序自然把它放在列之后、两个链之前，代价是三条链路的估算和）；两个输出哪个给谁（按消费者 `MinRate` 大的那一边离上游更近？放置规则按估算带长决定朝向，不需要我定）。

### 1.2 "谁来供某种物料"的规则

物料 → 家族，全部从游戏数据判断，不 if 物料名：

1. 物料是某个 `resource` 的产物 → 锚定采矿单元（要有矿区；给了矿区的资源才建矿，没给的走夹具——煤在本站就是夹具）；
2. 某个配方的主产物是它、且该配方的类别在冶炼列炉子的 `crafting_categories` 里 → 冶炼列；
3. 某个配方的主产物是它、类别在直插链默认机器的 `crafting_categories` 里 → 直插链；
4. 否则夹具。

同一物料有多个消费者 → 一个供给单元按需求之和定规模，中间插分离器（族 A）。处理顺序按配方深度从深到浅（绿瓶 5 → 爪子 4 → 绿板 3 → … → 板 1 → 矿 0），这样处理一种物料时它的所有消费者都已经生成、需求之和已知。红瓶站必须是这条规则的特例：同样的单元名、同样的 `free` / `links` 顺序（放置顺序与路由顺序依赖它），三行 `render` 逐字节不变——这是验收项，也是这条规则没有偷偷改变红瓶站的证据。

### 1.3 判断接口

- **选矿问题**：每种要开矿的资源一道题。候选 = 快照里 ≥ 50 格的全部矿区（半径 300，见 §0）；事实 = 格数、总矿量、外接矩形与位置、到出生点最近格的距离、到其他已选 / 候选矿区的距离、搜索区内的混矿、周围 45 格内的水与不可建格数、以及**采矿生成器在它上面按本站需求跑出来的数**（钻机数、带速率、`first_dry_s_lower_bound`、丢弃钻机原因）；默认答案 = 现行规则（最近）。
- **放置偏好问题**：`PlaceCosts` 五个权重 + 放置顺序优先级的含义与默认值。
- **答案文件**：`config/decisions/<name>.json`：`patches: {resource: candidate id}`、`place_costs: {...}`、`answered_by`、`rationale`。`fgen sweep site --decisions FILE` 读；行名加后缀 `@<name>`；没有文件 = 默认 = 现行行为（`render` 逐字节不变）。
- **回答者**：默认规则；Haiku（low）；Sonnet（low）；执行者本人。红瓶、绿瓶各一遍。弱模型只拿到问题文件与一页说明。

预期：选矿题上弱模型会选大矿（储量差 14 倍太显眼），代价是带长从几十格变成两百多格；放置权重上大概率保持默认或小改。实测看的是硬指标：路由带格 / 地下带、钻机数、`first_dry`、`fill_time`、放置重试、产率偏差。

### 迭代 2：绿瓶站离线规划（真实快照，默认选矿）——一个旋转 bug（00:45–01:05）

假设：绿瓶 1/s 站在真实快照上一次放通。

- 绿瓶链参数：第一次用默认（全调色板、`intermediates="auto"`）17 分钟没有首解（§0），改为 4b 特征化的那组（`GREEN_CHAIN`，`palette="given"`、只试道型）后 63 s 出周期（32×8 ×2，9 台机器/周期；输入：绿板右道 1/s、铁板左道 4.5/s）；绿板链 44 s（7×10，3 台）。

- **违例 1 个**：`power.disconnected`，电网两片。查到根因不在站点层：绿板链（全调色板）给自己的电口挑了**变电站**（2×2），链以 `E` 姿态放置后，接口里的杆格是把"格"旋转得到的，而 2×2 实体的 `position.floor()` 在旋转后落在另一格——差 1 格。电杆路由按接口格算变电站中心 (21,60)，实际在 (22,60)；它接出的小杆离真中心 8.3 格 > 7.5，`validate` 判断网。阶段 7 之前所有带电口的单元都是 1×1 小杆，这个 bug 从没触发过。
