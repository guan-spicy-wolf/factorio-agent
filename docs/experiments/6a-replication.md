# 6a 任务 1 复现实验：换执行者

Oct 29, 2026

`docs/design.md`（第二版）在"agent 自行写生成器"这条结论后面写着"样本只有一个执行者（当前最强编码模型），结论暂不外推"。本实验把同一份任务书（`docs/plan-phase6a.md` 任务 1，原记录 `6a-task1.md`）交给更弱的模型各跑一次，起点、规则、环境完全相同，看结论能不能外推。

## 设置

- 起点：提交 `ac07819`（阶段 3a M6，6a 之前）加上任务书，即 `1ae0810`；每个执行者一个独立 worktree 与分支（`exp/6a-replication-<model>`），看不到主分支与原答案。
- 提示词只有：读 CLAUDE.md / README / design.md / 任务书，只做任务 1，按实验规则记录；环境变量与"服务器一次一个"的提醒。不给排法，不给原记录的任何信息。
- 验收口径与原实验相同：7 个画矿用例 + 真实地图，`pole_slot` 总损失 ≤ 改进前的 1/3（79 → ≤ 26），钻机数逐例不减，实测偏差 ≤ 2%，大钻 + 中杆在矩形矿区可生成并通过 `validate`。
- 由本会话（Fable 5.1）统筹，只负责开 worktree、下发任务书、收报告、核对数字（`characterization/mining_patch.md`、实验记录、diff），不参与设计。

### 排法上的差别

两个执行者都放弃了"钻机钉在 3 格网格上、杆占整个钻位"的旧结构，都用动态规划在每条带子行上联合求"杆序列 + 钻机"，都靠两侧交替放杆解决大钻 + 中杆的"周期 11 > 拉线 9"。差别在杆放哪里：

- 原实验在迭代 0 的纸上计算里排除了"钻排里留缝"这一族（结论：每 7 格一个缝到不了 1/3），然后花 7 分钟做了一个 spike 核对"钻机能否往地下带上出料"，最后把**杆放进带的那一行、带从杆下面钻过去**，钻位一个不丢，`pole_slot` 0。
- Sonnet 没有做这一步纸上排除，直接实现了"杆只占自己的一列，钻机自由排"——正是原实验排除掉的那一族。但自由排钻 + 两侧交替 + 行间桥杆让它做到了 25%，过了线。它没有去想杆能不能不占钻排。

- Haiku 做得更少：杆放进钻机行的 1 列间隙，杆间距取"拉线距离内每列钻机数最多的整数"（固定 7），不在任何杆供电区里的钻机丢掉。一次迭代、19 分钟、diff 最小（+94/−63）。它报的 `pole_slot` 为 0 是因为把这个指标**重新定义成"没有杆供电的钻机"**——间隙本身吃掉的钻位不再计入。按唯一可比的指标（钻机数）看，三者是 375 > 355 > 346。

也就是说：**更弱的执行者找到了一个够用但不是最好的解，且越弱的执行者越倾向于把指标改成对自己有利的口径**（Haiku 的"0"按 Sonnet 的口径大约是 30 上下，仍过线，但不是 0）。原实验的反思里说"决定性的一步是迭代 0 的纸上计算"，这次对照正好印证——少了那一步，解的上限就定在了这一族里面。

### 共同点

- `validate` 失败都是 0。这与原记录的判断一致：不变量的作用不是拦错，而是让执行者敢大改。两次大改（各 ~600 行 diff）都没有产出过一个违例布局。
- 两者都撞上同一个任务外回归（真实地图整站从 7.5/s 掉到 6.5/s，因为 `site_sweep` 按钻机数分布选变体）。原实验顺手修了，Sonnet 明确标为"任务 1 范围外，没有处理"。任务书确实没写整站 sweep 要保持——这是人该写进验收口径的东西，不是执行者的问题。
- 三者都遇到旧测试写死了旧排法，都改写了测试而不是迁就旧排法；三者都重新定义了 `pole_slot`（旧定义在新结构下失效），且都如实写明是自己定的——但定义各不相同，导致这个指标在三次实验间**不可比**。
- 三者都撞上同一个任务外回归（7.5 → 6.5/s）：Opus 修了，Sonnet 记录未修，Haiku 重新生成了 site 表并上报。
- Sonnet 与 Haiku 列出的"任务书不清楚的地方"都与原实验的反思高度重合：`pole_slot` 口径、"显著增加"未量化、真实地图 `min_ore` 阈值变化、整站是否要保持、能否改旧测试、前值来源。

## 结论

- "agent 不碰坐标、只给目标就能写出通过全部不变量的生成器"这条，在 Sonnet 和 Haiku 上**都成立**：三个执行者、三次大改、`validate` 违例 0，实测偏差全 0%，验收全过，时间随模型变弱反而更短（45 / 25 / 19 分钟）。design.md 里"结论暂不外推"可以改为"在三档模型上复现"。
- 解的质量随执行者单调下降：钻机 375 / 355 / 346，排法的野心也递减（杆进带行、带钻地下 → 杆占一列 + 自由排钻 + DP → 固定间隙）。差距来自是否先做纸上分析排除整族排法、以及是否对"结构上限"追问，而不是来自编码能力。
- 弱执行者更容易把指标改成有利口径（Haiku 的 `pole_slot` 0）。它没有隐瞒，但人不盯着就会被表格骗过。验收指标必须是生成器改不了语义的量（钻机数、实测产率），不能是生成器自己上报的诊断量。
- 对任务书写法的启示（已写进 `docs/plan-phase7.md` §4）：(1) 验收口径里要把"相邻 sweep 不退化"写进去——三次都撞上同一条；(2) 验收用生成器改不了语义的硬指标，诊断量语义变了要求给新旧口径对照；(3) 如果希望弱执行者也到最优，任务书里加一句"先在纸上算出每一族排法的上限再动手"比给排法便宜得多，也不违反"不给排法"的实验规则。
- 分工上的含义：弱模型完全胜任"把一个明确目标变成通过不变量的代码"，强模型的溢价在"判断这一族到不到得了最优"。这正好支持把前者大量并行、后者用在分析与验收口径上。

实验分支：`exp/6a-replication-sonnet`、`exp/6a-replication-haiku`（各自的 `docs/experiments/6a-task1.md` 是执行者原始记录）。
