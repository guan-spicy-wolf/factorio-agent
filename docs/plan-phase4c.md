# 阶段 4c：随时可用的求解、目标预设、组件调色板

接续 `docs/plan-phase4b.md` 与 `docs/plan-phase5a.md`。实验规则沿用 `docs/plan-phase6a.md`，记录到 `docs/experiments/4c-anytime-palette.md`。

## 1. 动机

- "证明最小"只在当前模型词汇内成立（133 被加入长臂爪后的 108 打破），而面积从来不是目标，只是指标。真正重要的是迭代速度：agent 在循环里改生成器时，首个可行解要在秒级拿到。
- 解析预测与实测六轮偏差 ≤ 2%，仿真的价值在发现新结构的缺失不变量，不在复核算术。所以循环应是：可行解 → `validate` → 解析预测；仿真只在新结构或轮末回归时触发。
- 组件现在要人显式给候选（4a 的 108 依赖人想到加长臂爪）。应改为给一个调色板，求解器按成本自己选用子集。

## 2. 任务

### A. 随时可用模式（默认）

- 求解从**宽松尺寸**起步（解析上界：按机器占地、带行数、杆间距算出的保守 W×H；或调用方给定），先返回首个可行周期，再在时间盒内收紧（面积、然后目标函数），返回值标注 `proven: bool` 与各阶段耗时。
- "证明最小"保留为显式选项（`prove=True`），仅特征化表使用。
- 不可行判定改为时间盒：时间盒内无可行解 → 按不可行处理并标注 `unproven_infeasible`；能用必要条件（槛位计数等）秒判的先判。
- 测量并记录：4a/4b/5a 全部已有规格下，"首个可行解耗时 / 证明最小耗时"的比值表。

### B. 目标预设

硬约束不变（目标产率、配比、带道容量）。面积之后的目标做成预设，由调用方选：

- `compact`：面积 → 杆数 → 爪数（现状）。
- `cheap`：实体总成本 → 面积。成本从种子里的配方递归算到原矿价值（数据派生，不手填）。
- `simple`：不同实体种类数最少 → 面积。

### C. 组件调色板

- `CycleSpec` 的爪子、电杆、带等级从"指定一种（加可选 extra）"改为"调色板 + 成本"：每个槛位的种类是变量，可不用。调色板默认包含种子里该类型的全部实体，调用方可收窄。
- 带等级进调色板时道容量随之成为变量约束。地下带在周期内允许作为调色板项（采矿家族已用过）。
- 验证：**只给全调色板、不提示长臂爪**，3:2 绿板在 `compact` 预设下是否自己得出 108；`cheap` 预设下是否回到 133 并说明成本差；红瓶、塑料、硫酸在全调色板下结果不劣于 4b/5a。

### D. 仿真触发规则

- `fgen gen ...` 默认不起仿真；新增 `--simulate` 显式触发。sweep 的 `--measure` 不变。
- 在 README 写明仿真的两个触发条件：新实体类型或新结构词汇；轮末回归。

## 3. 验收

| 项 | 判据 |
| --- | --- |
| A | 已有全部规格首个可行解 ≤ 10 s（绿瓶 ≤ 60 s）；比值表进记录；`prove=True` 结果与 4b/5a 一致 |
| B | 三个预设在 3:2 绿板上给出可解释的不同解或说明为何相同；成本表由数据派生并有测试 |
| C | 全调色板不提示长臂得到 108；其余配方不劣于既有结果；求解时间记录 |
| D | 文档与 CLI 行为一致 |
| 记录 | 最后一节回答："首个可行解快在哪、慢在哪？调色板扩大后时间盒内收紧到什么程度？哪些预设在什么情形下值得用？" |

## 4. 约束

沿用全部约定。不改已有家族排法；不放宽不变量；OR-Tools 仍是可选依赖，穷尽搜索后端只需支持 `prove=True` 的旧行为。
