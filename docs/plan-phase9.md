# 阶段 9：求解器组合与试错对照——把"选择"做成可并发、可对照的机制

接续 `docs/plan-phase8.md` 与三份记录（`docs/experiments/8-green-science-site.md`、`8-solver-model.md`、`8-contract-buffer.md`）。本阶段的重心从"推进下一个配方"换到"求解器与选择机制"；配方（蓝瓶及以后）只作盲测材料出现。规则沿用 `plan-phase6a.md` 的实验规则与 `plan-phase7.md` §4，并按本文 §7 修订"不退化"的口径。全程记录到 `docs/experiments/9-<task>.md`。

## 1. 动机

阶段 7、8 的主体任务是红瓶站、绿瓶站，求解器只排在副线（7B、8C），两轮副线的数字目标都没达到（绿瓶首解 ≤ 10 s 只在确定性口径达到；12 台周期 600 s 无解；红瓶 1:10 证不完）。而每推进一个配方都要人手钉一组参数：绿瓶链钉了 `GREEN_CHAIN`（给定调色板、长臂爪、只试道型、`max_lane_consumers=6`），因为默认参数 17 分钟没有首解；`intermediates="auto"` 要把已知不可行的直插型逐个烧完 60 s 才到可行的道型。这些手钉的参数就是现状与"agent 辅助即可完成"之间的全部距离。

6a 复现实验给出的分工是：验收全过，但解的质量随模型变弱单调下降，差距在纸上分析而不在编码。也就是说**不能依赖模型的灵机一动或性能**。模型可靠的长处是另一件事：**同时开几条路、按硬指标并排看、选一个**。本阶段把这件事做成机制：

- 求解器层：组合驱动（portfolio），多个成员并发、先出解者赢、盒内按预设键取最优，而不是顺序烧时间盒；
- 工具层：通用的变体运行器与对照表（`fgen compare`，架子已搭，见 §9），任何一次选择都有一张表撑着；
- 规则层：进仓库的每个选择（钉住的参数、答案文件、任务书里的"取 X"）都指向它所依据的那一行，不许凭记忆钉。

最终目标不变：每一步做扎实，火箭是水到渠成的事。但到火箭的路上不再每个配方付一次人肉特征化。

## 2. 目标与分工原则

**目标**：给定产品与产率，agent 在不改生成器代码、不写坐标、不凭记忆钉参数的前提下，用对照表选出链参数、站点判断题的答案，一条命令规划、路由、实测达标。"agent 辅助"是允许的，"靠 agent 想出排法"不是。

**分工**（在 `docs/design.md`"agent 的角色分工"之上细化）：

| 工作 | 负责方 | 说明 |
| --- | --- | --- |
| 周期内摆放、配比、规模、放置、路由 | 算法 | 不变 |
| 一组候选同时求解、按键取优 | 算法（组合驱动） | 任务 A |
| 决定开哪些变体（搜索空间怎么切）、读失败决定下一批 | agent | 用变体文件表达，不碰代码 |
| 从对照表里选一行 | agent 或人 | 选择要写进产物并指向那一行 |
| 带目标的判断题（选矿要跑多久、面积预算） | agent | 目标进问题文件（8A §4 第 2 点） |
| 想出新排法、新结构词汇 | 人 + agent（实验，不在主线） | 6a 的模式，另开实验 |

## 3. 任务 A：直插链组合驱动

**现状**：`DirectChain.generate` 按 `plans()` 的顺序逐个周期类型调 `period_for`，每个选项一份 `time_limit` 的确定性预算，前一个烧完才到下一个；调色板第 0 级（只用首选等级）与第 1 级也是顺序的。7B 的 B3 已把证明驱动里互相独立的模型放进多进程（`cpsat.PROCS`），解集不变、只改墙钟。

**目标**：组合驱动——把"周期类型 × 调色板级别 × （必要时）尺寸族"的候选作为成员并发求解；首个可行成员一出来就是首解（其余成员继续到各自预算用完或被取消），时间盒结束时按预设键取最优；每个成员各自一份确定性预算，所以同一规格并发与否给同一组候选，只是墙钟不同。

**数字验收**（4 核、与阶段 8 同口径记负载）：

| 项 | 判据 |
| --- | --- |
| 不钉参数 | 绿瓶 0.5/s 用默认参数（全调色板、`intermediates="auto"`、`max_lane_consumers` 默认）在 60 s 盒里有首解，墙钟不超过钉了 `GREEN_CHAIN` 的 1.5 倍 |
| 不变慢 | `solver_time` 其余用例首解（确定性与墙钟）不变慢 |
| 不退化 | `direct_chain` / `fluid_chain` / `palette` 的 prove 行周期不变；随时可用行允许换解，但按各自预设键不得更差，变了的行按 §7 重测 |
| 终解质量 | 60 s 盒终解按预设键不比 8C 的 29×8 / 7 杆 / 26 爪差 |
| 取消 | 成员被取消时不留下子进程；`PROCS` 与成员数的乘积有上限（一个 CP-SAT 模型约 1.5 核） |

**规则 1 照旧**：动手前写下候选切法的几族（按周期类型 / 按调色板级别 / 按高度 / 混合）、各自成员数与预算分配、排除了哪些；8C 的静态剪枝（S）要先把明知不可行的成员否掉，不开进程。12 台绿瓶、红瓶 1:10 的证明不是本任务目标，但要给出组合驱动下的进度。

## 4. 任务 B：变体运行器与对照表（架子已搭）

本次已交付（§9）：`src/fgen/compare/`、`fgen compare FILE`、`config/variants/`、`compare/`。剩下的：

- 家族：加采矿（变体要带地形快照与矿区：快照存 JSON、矿区按 `decide.patch_id`）与站点（变体 = 答案文件 + 链参数集，`fgen sweep site --decisions` 现在的能力并进来，行名 `@name` 的约定保留）。
- 决赛实测：`--measure TOP_K`，只对排名前 k 的成员起服务器实测（试错的梯子：`validate` → `predict` → 离线放置路由 → 求解 → 实测，广度放在便宜的级）。
- 续跑：成员多、机器满时能中断续跑（按 `variant` 名与 `params` 键跳过已有行）。
- 表：同一张表多次运行的差异（成员增删、换解）要能看出来；`asked_by.question` 与选中的行写回变体文件的 `chosen` 字段。
- 现有 sweep 模块（`direct_chain_sweep`、`fluid_sweep`、`palette_sweep`、`solver_time_sweep`、`site_sweep` 的表部分）是否并入 `compare`：先不动（它们是回归表，键是 `params`），等 B 的家族补齐后再定；`docs/scripts.md` 标了每张表的去向。

**验收**：绿瓶链变体表（`config/variants/green-chain.json`）能回答"当年为什么钉 `GREEN_CHAIN`"——表里有默认参数那一行的结果（有首解 / 无首解、多少秒）；一次站点级对照（红瓶或绿瓶 × 两份答案文件 × 两组链参数）由 `fgen compare` 一张表给出，不再手写脚本；`uv run --extra solver pytest -m "not headless"` 全绿。

## 5. 任务 C：诚实的失败与可复现的单次试验

对照表有意义的前提是每一行都诚实、每一次重跑都一样。现状里三处不满足：

1. **`MinRate` 不足不拦**：路由时契约检查 `ok: False` 只记警告，绿瓶 1 档铁矿 9 台钻（契约 4.5 < 5.5）实测达标全靠全科技 +30% 采矿加成（8A 迭代 6）。改为 `plan_and_connect` 把失败的 `MinRate` 当错误（站点行变成 `infeasible`），或 `choose_mining` 按运行时状态算；两种都要给出对现有行的影响表。
2. **终解随墙钟走**：证明驱动的终解模型吃剩余墙钟作 `max_time_in_seconds`，硫酸 r100、红瓶 1:10 同一代码两次给不同放置（8C F1/F2）。终解模型改用确定性时间上限；拉线连通改为求解回调里检查并保留最好的连通解（8C 待办第 1 条）。
3. **墙钟上限触顶会换解**：随时可用驱动的 `WALL_FACTOR` 在机器被占满时会被触到。并发之后这一条更常见。要么盒子完全按确定性时间（墙钟只作保险并在触到时把行标成 `wall_capped`），要么表里显式标出。

**验收**：三类现有表重跑两次（一次安静、一次与另一组求解并行）逐字节相同，或差异行全部带 `wall_capped` 标记；`site.jsonl` 里不再有 `ok: False` 却判 `ok` 的行。

## 6. 任务 D：盲测配方

挑一个从未特征化的配方（候选：`engine-unit`、`advanced-circuit`、`military-science-pack`，或蓝瓶整站的一层），用 A、B、C 交付的机制走一遍：开变体 → 读表 → 选行 → 站点规划 → 实测。

**允许**：写变体文件、读表、选行、写答案文件、改 `asked_by.question` 再开一批。
**不允许**：写坐标；改生成器 / 求解器代码（发现 bug 另开分支修，记录）；凭记忆在代码或场景函数里钉参数。
**记录**：每一个"不得不"违反上面规则的地方就是 A、B、C 的缺陷，逐条进 §待办；达标与否之外，这张清单是本任务的主要产物。

## 7. 实验规则修订

沿用 6a 规则与 `plan-phase7.md` §4，修订一条：

- **"相邻 sweep 不退化"的口径**：退化指**产率、不变量、按预设键的解质量**变差，不指蓝图字节变化。8C 为了"蓝图逐字节不变"把静态剪枝限制在只看状态的模型上，`PRUNE_ALL` 的首解 7.9 s、终解等于证明最小却被弃用——保护实测数据是对的，但以蓝图不变为验收会让求解器每一步改进都给旧解让路。新口径：改了求解器后，特征化表里换了解的行按预设键对照（不得更差），实测丢的行在本轮或合并前重测补回；表里 `measured` 为空的换解行不算达标。

其余不变：不放宽不变量、不写死数字、不 if 实体名、先在纸上排除整族、指标语义变了给新旧口径、失败也记。
