# Factorio 蓝图生成：从坐标设计到生成器

Oct 24, 2026 · @holo

## 背景与动机

上一版卡住的根因是：设计 agent 工作在坐标层级，而蓝图只记录结果、不记录约束。本方案把 agent 的产出从“一张蓝图”改为“能生成一类蓝图的程序”。

上一版流程分四个阶段：

1. **选址**：agent 看地图，圈定范围和地形约束，拆出几个大单元（如采矿区、冶炼区）。
2. **设计**：每个单元由一个设计 agent 在地形约束内逐格摆放，产出带输入输出口的蓝图。
3. **仿真测试**：每张蓝图在 headless 中部署，输入无限供应，不达标则退回设计。
4. **部署**：在真实存档中放置，单元间连接由算法完成，再测各项参数。

暴露出的问题都集中在第二阶段和锚定建筑上：

- **脚手架随约束种类线性增长**：每多一类约束（液体相邻、固定朝向、地下带长度），就要多一套校验和提示去教 agent。
- **改进现有蓝图效果差**：实体列表里没有“为什么这样摆”，agent 必须先反推隐含约束才能改，比从零设计更难。
- **社区蓝图用不上**：交给 agent 的仍是实体列表，可复用的周期结构没有被提取出来。
- **液体和固定建筑卡死**：抽油机、海水泵的位置和朝向由地图决定，不符合“先在真空里设计、再部署”的假设，问题直到第四阶段才暴露。

## 目标与非目标

首要目标是验证：用生成器代替逐格设计后，给定目标产率能稳定产出可部署、达标的单元，且新增约束不再需要新增 agent 脚手架。

**目标**

- 给定产品和目标产率，自动产出达标的自由单元（先覆盖冶炼列和 3:2 绿板直插链）。
- 锚定单元（采矿、抽油、海水泵）在真实地图上由算法生成，其接口作为自由单元的硬约束。
- 以上帝建造模式在真实地图上部署：不处理移动、背包和资源消耗，但地形约束照常生效（水域、悬崖、资源格、已有建筑、不可建造地块）。产出的是放进地图里的工厂，不是脱离地图的蓝图。
- 每个生成器家族有参数扫描和特征化表，选参数靠查表而不是每次重新仿真。
- agent 的输出是参数或生成器代码，不是坐标。

**非目标（本轮不做）**

- 千瓶级、信标优化、UPS 优化的布局。
- 让 agent “玩”游戏（移动、背包、手工建造）；地形约束不在此列，见目标。
- 全局最优的宏观排布；宏观层面先用简单的规则排布。
- 面积极致压缩；面积只作为特征化里记录的一个指标。

**成功标准**

| 判据 | 衡量方式 |
| --- | --- |
| 自由单元达标率 | 指定产率下，生成结果在 headless 中实测吞吐 ≥ 目标的比例 |
| 零坐标修改 | 从参数到达标单元，过程中没有 agent 手改坐标 |
| 新约束的成本 | 新增一类约束时，改动只落在几何库或生成器，不改 agent 提示 |
| 部署一致性 | 真实存档中实测吞吐与特征化表的预测相符 |
| 端到端 | 从选址到真实存档达标，完成一条铁板线和一条绿板线 |

## 核心方法

核心转变是：蓝图是 `generate(p)` 在某组参数下的一个输出，我们维护的是生成器本身。生成器里的不变量由构造保证，而不是事后检查。

### 自由单元与锚定单元

- **自由单元**：可在真空里设计，带输入输出口，可平移、旋转、镜像后放入地图。例：冶炼列、组装链。
- **锚定单元**：几何形状和接口位置由地图决定。例：采矿（矿区形状）、抽油机（油井位置）、海水泵（岸线和朝向）。
- 锚定单元先做，不经过设计 agent，直接由算法在真实地图上生成；它们的接口位置和朝向成为后续自由单元的硬约束。

### 周期与生成器家族

- 单元的结构是“头部 + 周期 × n + 尾部”。周期是配比的最小整数组，不一定是一台机器（3:2 绿板链的周期是 3 台铜线机 + 2 台绿板机）。
- 生成器按家族组织，家族很少、配方很多：
  1. 带供料的行（单配方，输入数不超过带道数）
  2. 配比周期的直插链
  3. 二维周期（信标阵列，本轮不做）
  4. 固定布局（零参数，只允许旋转和镜像）
- 配比不整齐时：要么用近似整数比让一侧略过剩，要么退化为两段行结构，用带子传中间产物。

### 周期内求解与周期边界条件

- 周期内部可写死（已知经典排法），也可交给 CP-SAT 在小区域内精确求解。
- 约束包括：直插两端机器隔一格相邻、爪子取放格合法、电杆覆盖周期内所有用电实体、管道不意外相邻。
- **周期边界条件**：带子在周期两端对齐、电杆跨周期能连上。没有它，单个周期合法、拼起来会断。

### 接口契约

每个单元输出一个接口列表，第四阶段的连接算法只看它：

- 类型（物品、液体、电）、物料、位置、朝向、带道
- 需要或提供的速率
- 假设条件（如“输入带满压缩”“矿在左道”）

### 特征化

- 对每个生成器做参数扫描，每个组合在 headless 中跑一次，记录实测吞吐、启动时间、面积、对输入不满载的敏感程度。
- 结果存成表。选参数时查表，不再每次仿真。爪子摆动、带上物品分布等细粒度效应在这一步被吸收成单元属性。

### 组件树与容器

- 叶子是一个周期的解或一个固定布局；容器负责子组件之间的边界和连接语义。
- 和前端布局的关键区别：Factorio 里相邻即连接（爪子、管道自动连通、电杆覆盖跨边界、侧向汇入），所以容器必须懂连接语义，不能只做排列。

```python
Column(
    Row(Smelter(furnace="steel"), repeat=24, join="belt"),
    Balancer(4, 4),
    Row(DirectChain(cable=3, circuit=2), repeat=8, join="belt"),
)
```

## 系统分层与组件

系统分七层，自上而下从游戏数据走到可部署的蓝图；agent 只从侧面进入组件树和生成器家族，不碰坐标。

&#91;embedded content: 系统分层 · 左列为主数据流，右列为求解器、agent 与反馈\]

左列是确定性的数据流，每层只依赖上一层。右列的周期求解器为生成器家族提供周期内的摆法；仿真与特征化把结果回传给 agent，用于选参数和决定改什么。

- **游戏数据导出**：`--dump-data` 输出的原型 JSON，mod 实体一并包含，是几何库的唯一数据来源。
- **几何库**：回答“实体占几格、爪子从哪取往哪放、电杆覆盖哪里、液体接口在哪、旋转镜像后怎么变”。
- **生成器家族**：每个家族一个生成函数，附带不变量检查；输出布局和接口契约。
- **组件树与容器**：声明式描述单元组合，容器负责子组件之间的带子对齐、电杆连通、管道隔离。
- **导出器 / 部署器**：前者产出蓝图字符串，后者通过 RCON 直接在 headless 或真实存档中放置。
- **仿真与特征化**：参数扫描得到特征化表；部署后的结构化诊断（如某列输入饥饿比例）回传给 agent。

## agent 的角色分工

原则：确定性计算和几何交给算法，判断和写代码交给 agent，家族划分和不变量交给人。

| 工作 | 负责方 | 说明 |
| --- | --- | --- |
| 配比、炉数、列数、电杆间隔 | 算法 | 生成器内部派生，不经过 agent |
| 锚定单元生成 | 算法 | 钻机铺矿、抽油机管网、海水泵贴岸 |
| 周期内摆放 | 算法 | 经典排法写死，或 CP-SAT 求解 |
| 单元间连接 | 算法 | 只读接口契约，做带子和管道路由 |
| 选址与单元拆分 | agent | 对应原第一阶段，输出改为单元列表 + 锚定单元接口 |
| 选家族与参数 | agent | 查特征化表，写组件树 |
| 读诊断、决定改什么 | agent | 仿真和部署的结构化诊断，如“第 3 列输入饥饿 40%” |
| 写新生成器 | agent | 没有合适家族时；须通过参数扫描和不变量检查才入库 |
| 几何库、导出器 | agent（一次性编码） | 用往返测试验证 |
| 家族划分、不变量是否写全 | 人 | 决定整个库的上限 |

原第二阶段的设计 agent 不再存在，它的工作拆成“选参数”和“写生成器”两种。

## 实施阶段

先打通底座和一个最简单的家族，再逐步加难度；锚定单元放在早期，因为它是上一版实际卡住的地方。每个阶段有明确的完成判据，没过判据不进下一阶段。

**阶段 0：底座**

- 产出：游戏数据导出（`--dump-data`）；几何库（占地、爪子取放格、电杆覆盖、液体接口、旋转镜像变换）；导出器；headless 部署器（RCON）；地形查询（可建造格、水域、悬崖、资源格、已有建筑）。
- 完成判据：手写几个实体列表，生成蓝图后在 headless 中导入放置，读回实体列表与原列表一致（往返测试）。

**阶段 1：第一个家族——冶炼列**

- 产出：带供料行家族的生成器，冶炼列实例；不变量检查；参数扫描与特征化表。
- 完成判据：给定 5、15、30 铁板/秒，生成结果在无限供应下实测达标；改电杆类型或熔炉类型时只改参数。

**阶段 2：锚定单元——采矿**

- 产出：在真实地图副本上铺钻机的生成器，输出接口契约。
- 完成判据：在真实地图副本上测出矿产率，并与契约里的速率一致。

**阶段 3：端到端铁板线**

- 产出：选址 agent（输出单元列表 + 锚定接口）、单元间连接算法、真实存档部署。
- 完成判据：从目标产率到真实存档达标，过程中无人手改坐标。

**阶段 4：第二个家族——直插链**

- 产出：周期求解器（CP-SAT，带周期边界条件）；3:2 绿板链；组件树与容器。
- 完成判据：求解器自动得到的周期，平铺 n 次后在仿真中达标；与写死的经典排法对比吞吐和面积。

**阶段 5：液体与固定建筑**

- 产出：海水泵、抽油机等锚定单元；液体接口在几何库与契约中的表示；液体相关不变量。
- 完成判据：一条带液体输入的产线端到端达标，新增工作只落在几何库、生成器和不变量里。

**阶段 6：agent 写生成器**

- 产出：给 agent 一个库里没有的配方，由它写新生成器，经参数扫描和不变量检查后入库。
- 完成判据：新生成器一次或少量迭代通过检查，产出单元达标。

社区蓝图的周期提取不单列阶段：阶段 4 之后可作为周期求解器的种子来源试接。

## 风险与开放问题

最大的风险是周期求解器的编码成本：如果约束写起来比手写模板还难，阶段 4 应退回“写死经典排法 + 参数化”。

- **游戏版本**：1.1 与 2.0 的液体系统不同，几何库和液体不变量要按版本写。目标版本定为 2.0；初期不进太空，太空时代是否启用只影响导出的数据集，阶段 0 按实际启用的 mod 组合导出即可。
- **周期求解规模**：周期变大（配比不整齐）时 CP-SAT 可能变慢；退路是近似整数比或拆成两段行结构。
- **跨边界效应**：特征化基于接口契约的假设（如输入满压缩），真实存档里上游不满载时，预测会偏。阶段 3 要专门对比预测与实测。
- **容器的连接语义**：管道意外相邻、电杆跨组件覆盖、侧向汇入，这些交互能否都收进容器而不泄漏到叶子，未知。
- **锚定单元的多样性**：矿区形状不规则、油井分散，算法在边角情况下可能产出低效布局；本轮只要求可用，不要求最优。
- **mod 实体**：方向控制等 mod 是否都能从数据导出中拿到足够信息（取放格偏移等），需在阶段 0 确认。
- **agent 写生成器的可靠性**：阶段 6 能否稳定通过检查是本方案对模型能力的唯一实质性押注。

## 附录：关键数值与术语

以下数值按记忆整理（早期配方 2.0 与 1.1 应一致），未经查证，阶段 0 应以数据导出为准。

| 项 | 值（近似） | 用途 |
| --- | --- | --- |
| 铁板配方 | 3.2 秒，1 矿出 1 板 | 炉数计算 |
| 石炉 / 钢炉合成速度 | 1 / 2 | 单炉产率 0.3125 / 0.625 每秒 |
| 黄带总速率 | 15 每秒（单道 7.5） | 单列上限：一条矿道约喂 24 台石炉 |
| 铜线配方 | 0.5 秒，1 铜板出 2 铜线 | 绿板配比 |
| 绿板配方 | 0.5 秒，1 铁板 + 3 铜线 | 铜线机 : 绿板机 = 3 : 2 |

**术语**

- **自由单元 / 锚定单元**：可在真空里设计并平移的单元 / 几何由地图决定的单元。
- **周期**：单元内重复的最小结构，配比的最小整数组。
- **周期边界条件**：保证周期平铺后带子对齐、电杆连通的约束。
- **生成器家族**：一类结构的生成器（行、直插链、二维周期、固定布局）。
- **接口契约**：单元对外的口及其速率和假设条件。
- **特征化**：对生成器参数扫描后实测得到的性能表。
- **容器 / 叶子**：组件树中负责连接语义的节点 / 一个周期的解或固定布局。
